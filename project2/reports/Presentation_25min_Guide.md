## ส่วนที่ 2: คำถามคุณภาพสูง 3 คำถาม สำหรับใช้ถามกลุ่มอื่น (ได้คะแนน 2% สำหรับคำถาม)

เกณฑ์การให้คะแนนระบุว่า *"สามารถให้ข้อเสนอแนะ หรือซักถามความเข้าใจในงานของกลุ่มอื่นได้ ด้วยคำถามที่เหมาะสม และมีความรู้ 3 คำถาม (2% คิดต่อกลุ่มสำหรับคำถาม)"* สามารถเลือกใช้ 3 คำถามนี้ถามกลุ่มอื่นได้ทันที:

### คำถามที่ 1 (ด้านการออกแบบฟังก์ชันและการนำกลับมาใช้ซ้ำ — Modular Reusability & Data Coupling)
> **"ในการแยกฟังก์ชันย่อยออกเป็นคนละโมดูล (Module) กลุ่มของเพื่อนจัดการโครงสร้างข้อมูลที่ส่งต่อระหว่างฟังก์ชันหลักกับฟังก์ชันย่อยอย่างไร (เช่น ใช้ `dict`, `tuple`, หรือ `dataclass`) และหากต้องการนำฟังก์ชันย่อยเพียงโมดูลเดียวไปใช้กับข้อมูลชุดใหม่ของสิ่งมีชีวิตชนิดอื่น จะสามารถเรียกใช้แยกเดี่ยว ๆ โดยไม่ต้องแก้ไขโค้ดภายในฟังก์ชันได้หรือไม่ เพราะเหตุใด?"**
- **จุดประสงค์ของคำถาม:** ทดสอบความเข้าใจเรื่อง Function Encapsulation, Parameterization, Return Types และการหลีกเลี่ยง Global Variables ตามหลักการเขียนฟังก์ชันที่ดี

### คำถามที่ 2 (ด้านการจัดการความผิดปกติของข้อมูลทางชีวสารสนเทศ — Biological Edge Cases & Input Validation)
> **"ข้อมูลทางชีวโมเลกุลจากฐานข้อมูลจริงมักพบความไม่สมบูรณ์ เช่น ลำดับเบสที่มีตัวอักษรกำกวม (`N`), ลำดับความยาวไม่ครบสมบูรณ์ (Partial sequence) หรือตารางข้อมูลที่มีค่าสูญหาย (Missing values) ฟังก์ชันย่อยของกลุ่มเพื่อนมีการตรวจสอบความถูกต้องของพารามิเตอร์ขาเข้า (Input Validation / Exception Handling) อย่างไรเพื่อป้องกันไม่ให้ผลลัพธ์ทางชีววิทยาคลาดเคลื่อน?"**
- **จุดประสงค์ของคำถาม:** ทดสอบการเชื่อมโยงความรู้ด้านชีวสารสนเทศศาสตร์ (Sequence QC / Data Cleaning) เข้ากับการดักจับข้อผิดพลาดในโปรแกรม (`ValueError`, `try-except`, filtering conditions)

### คำถามที่ 3 (ด้านความซับซ้อนของอัลกอริทึมและการขยายขนาดข้อมูล — Scalability & Algorithmic Complexity)
> **"หากขนาดของข้อมูลนำเข้าเพิ่มขึ้นเป็นระดับหลายแสนรายการหรือจีโนมขนาดใหญ่หลายพันสายพันธุ์ ฟังก์ชันย่อยในโมดูลใดของกลุ่มเพื่อนจะเป็นจุดคอขวด (Bottleneck) ที่ใช้เวลาหรือหน่วยความจำ (RAM) มากที่สุด และในเชิงการเขียนโปรแกรมสามารถปรับโครงสร้างข้อมูล (เช่น เปลี่ยนจาก `list` เป็น `set`/`dict` หรืออ่านแบบ Streaming) เพื่อลดเวลาการทำงานได้อย่างไร?"**
- **จุดประสงค์ของคำถาม:** ทดสอบความเข้าใจเรื่องชนิดข้อมูลใน Python (`list` $O(n)$ lookup เทียบกับ `set`/`dict` $O(1)$ lookup) และการใช้หน่วยความจำเมื่อประมวลผลข้อมูลชีวสารสนเทศขนาดใหญ่

## ส่วนที่ 3: แนวคำตอบสำหรับกลุ่มเรา เมื่อถูกอาจารย์หรือกลุ่มอื่นถาม (ได้คะแนน 2% สำหรับคำตอบ + 2% รายบุคคล)

### Q1: ทำไมต้องแยกฟังก์ชันออกเป็น 5 โมดูล และมีการเรียกใช้ฟังก์ชันข้ามโมดูลอย่างไร?
- **แนวคำตอบ:** เราออกแบบตามหลัก **Single Responsibility Principle (SRP)** และ **Modularity** โดยแยก 1 โมดูลหลัก (`main_pipeline.py`) และ 5 โมดูลย่อย (`mod1` ถึง `mod5`) ตามขั้นตอนทางชีวสารสนเทศศาสตร์ นอกจากนี้ยังพิสูจน์การนำกลับมาใช้ซ้ำ (Reusability) จริงภายในโปรเจกต์ เช่น ฟังก์ชัน `parse_fasta_records()` ที่เขียนไว้ใน **Module 2** (`mod2_genome_fetcher.py`) ถูกนำมา `import` และเรียกใช้ซ้ำโดย **Module 3** (`mod3_amr_gene_scanner.py`) เพื่ออ่านไฟล์ยีนดื้อยาอ้างอิง โดยไม่ต้องเขียนโค้ดอ่าน FASTA ซ้ำสองรอบ และตารางเกณฑ์ `CLSI_DRUG_BREAKPOINTS` ใน **Module 4** ก็ถูกนำมาใช้ซ้ำใน **Module 5** เพื่อจำแนกค่า MIC

### Q2: ทำไมเชื้อที่มีแต่ยีน `blaTEM-1` (เช่น สายพันธุ์ `EC_GEN_003`) จึงดื้อต่อยา Ampicillin (`AMP = NS`) แต่ยังไวต่อยา Amoxicillin/Clavulanate (`AMC = S`)?
- **แนวคำตอบ:** ในเชิงชีวโมเลกุล ยีน `blaTEM-1` สร้างเอนไซม์ Class A broad-spectrum $\beta$-lactamase ซึ่งสามารถไฮโดรไลซ์วงแหวน $\beta$-lactam ของยา Ampicillin ได้โดยตรง ทำให้ค่า MIC พุ่งขึ้นเป็น $32\ \mu\text{g/mL}$ ($\ge 16\ \mu\text{g/mL}$ จึงเป็น `NS`) แต่ในยา `AMC` มีสาร **Clavulanic acid** ซึ่งเป็น $\beta$-lactamase inhibitor ที่เข้าจับและยับยั้งเอนไซม์ TEM-1 ได้ ทำให้ค่า MIC ของ `AMC` อยู่ที่ $8\ \mu\text{g/mL}$ ($\le 8\ \mu\text{g/mL}$ จึงยังเป็น `S`) เชื้อจะดื้อต่อ `AMC` (`NS`, $\text{MIC} \ge 16\ \mu\text{g/mL}$) ก็ต่อเมื่อมียีนที่สร้างเอนไซม์ที่ Clavulanate ยับยั้งไม่ได้ เช่น `blaOXA-1` (Class D oxacillinase) หรือ `ampC` (Class C cephalosporinase) ซึ่งโปรแกรมใน `mod4_genotype_phenotype_map.py` ได้แยกเงื่อนไขกลไกนี้อย่างชัดเจน

### Q3: ทำไมการดื้อยา Ciprofloxacin (`CIP`) และ Nitrofurantoin (`NIT`) จึงต้องตรวจหา Point Mutations แทนการตรวจหาแต่ยีนบนพลาสมิด?
- **แนวคำตอบ:**
  1. สำหรับ **Ciprofloxacin (กลุ่ม Quinolones)** กลไกหลักของการดื้อยาระดับคลินิก ($\text{MIC} \ge 2\ \mu\text{g/mL}$) ใน *E. coli* เกิดจากการกลายพันธุ์แบบขั้นบันได (Stepwise mutations) บนโครโมโซมในบริเวณ **QRDR (Quinolone Resistance-Determining Region)** ของยีนเป้าหมาย `gyrA` (ตำแหน่งกรดอะมิโน Ser83Leu และ Asp87Asn/Tyr) ร่วมกับ `parC` (ตำแหน่ง Ser80Ile และ Glu84Val) ส่วนยีนพลาสมิด `qnrS1` เพียงอย่างเดียวจะลดความไวเพียงเล็กน้อย แต่ถ้าพบร่วมกับ `gyrA` S83L จะเสริมฤทธิ์กันจนข้ามเกณฑ์ดื้อยา
  2. สำหรับ **Nitrofurantoin (`NIT`)** เป็นยาในรูป Prodrug ที่ต้องอาศัยเอนไซม์ Nitroreductase ภายในเซลล์แบคทีเรีย คือ **NfsA** และ **NfsB** ในการเปลี่ยนตัวยาให้เป็นรูปที่ออกฤทธิ์ทำลาย DNA ของแบคทีเรีย ดังนั้นการดื้อยา `NIT` จึงเกิดจากการกลายพันธุ์แบบสูญเสียหน้าที่ (Loss-of-function / Nonsense stop codon `*` หรือ Missense ในตำแหน่งกัมมันต์ เช่น `nfsA_R15C`/`nfsA_R15*` ร่วมกับ `nfsB_W94*`/`nfsB_Q44*`) ซึ่งฟังก์ชัน `detect_qrdr_and_nitroreductase_mutations()` ใน **Module 3** ทำการแปลรหัสพันธุกรรมจาก DNA เป็นกรดอะมิโนด้วย `BACTERIAL_CODON_TABLE` เพื่อตรวจจับโดยตรง

### Q4: โปรแกรมจัดการข้อมูลคลินิกขนาดใหญ่ 574,239 แถวอย่างไรให้ใช้หน่วยความจำต่ำและทำงานเสร็จภายในไม่กี่วินาที?
- **แนวคำตอบ:** ใน **Module 1** (`load_and_profile_clinical_resistance`) เราใช้ `csv.DictReader` อ่านไฟล์ทีละแถวแบบ **Streaming Iterator** โดยไม่โหลดทั้งตารางเก็บเป็น `list` ของแถวใน RAM แต่สะสมเฉพาะค่าตัวเลข MIC ลงใน `defaultdict(list)` และใช้โครงสร้างข้อมูล `set` เก็บรหัสสายพันธุ์ (`all_isolates`) และกลุ่มยาที่ดื้อ (`isolate_ns_classes`) ซึ่งการค้นหาและตัดค่าซ้ำใน `set` มีความซับซ้อนเชิงเวลาเพียง $O(1)$ ทำให้ประมวลผลข้อมูลกว่าครึ่งล้านแถวเสร็จภายในเวลาประมาณ 6–7 วินาที
