รายงานสรุปโปรแกรม Python ที่รันใน venv และตรวจสอบข้อมูลต้นทาง

1. วัตถุประสงค์และผลลัพธ์

อ่าน all_drug_2023.xml เป็นค่าเริ่มต้นตามโจทย์ สร้าง Drug_Target.csv หนึ่งรายการต่อหนึ่งยา มีรหัส ชื่อสามัญ counts ของ targets, enzymes, IonChannel และ transporters แล้วตามด้วยรายละเอียดทุก interaction entry ชุดละ 6 คอลัมน์:

protein_number, protein_name, organism,
actions, Uniprot_ID, gene_name

รูปแบบหลักใช้วงเล็บเหลี่ยมครอบแต่ละชุดตามภาพโจทย์และแถวที่ไม่มีเป้าหมายจบที่ 6 คอลัมน์ header ครอบคลุมจำนวนชุดสูงสุดในข้อมูล มีรูปแบบตารางเสริมสำหรับการวิเคราะห์ที่เติมช่องว่างให้ทุกแถวเท่ากัน

2. โครงสร้าง 3 ขั้นตอน: อ่าน → เขียน → ตรวจ

ไฟล์การทำงานสำคัญ
drugbank_parser.pyใช้ ElementTree.iterparse อ่านทีละยา รองรับ namespace เลือกรหัส primary และสกัด 4 หมวด จากนั้นนำ node ออกจาก root เพื่อคืนหน่วยความจำ
group3.pyพักข้อมูลใน spool บนดิสก์เพื่อทราบจำนวนชุดสูงสุด เขียนด้วย csv.writer เป็น UTF-8 BOM ตรวจสอบก่อนแทนที่ไฟล์ CSV เดิม และสร้างรายงาน JSON
verify_output.pyอ่าน XML ซ้ำด้วยตรรกะอิสระ ไม่เรียกตัวสกัด เทียบทุก cell ทุกแถว พร้อมเก็บตัวอย่างต้น/กลาง/ท้ายและ SHA-256 ของไฟล์

สร้าง .venv ด้วย Python 3.14.4 และใช้ standard library จึงไม่มี dependencies ภายนอก มี comments/docstrings ภาษาไทยและชื่อฟังก์ชัน/ตัวแปรที่สื่อความหมายตามข้อกำหนด

3. หลักการสกัดและจัดการกรณีพิเศษ

  • XML นับ entry ใน targets → enzymes → carriers → transporters และเรียงตามลำดับ XML ภายในหมวด protein_number เริ่ม 1 ใหม่ทุกหมวดภายในแต่ละยา ไม่ตัดโปรตีนที่ซ้ำแต่ทำหน้าที่ต่างกันออก
  • ใช้ชื่อและ organism ของ entry ก่อน; UniProt ใช้ attribute id ของ polypeptide และ gene ใช้ gene-name ไม่ใช้รหัส BE ของ target เป็น UniProt
  • ไม่มีข้อมูลใส่ Nan ตามโจทย์ ยังเก็บ non-protein target เช่น DNA หลาย actions หรือ polypeptides คั่นด้วย | โดยรักษาคู่ ID/gene และตำแหน่งที่หาย; JSON เก็บชื่อ/organism ของทุก subunit ใน complexes
  • เลือก drug ชั้นบนสุดและใช้ namespace-aware parser ไม่เอา drug ใน pathways มานับเพิ่ม XML ขาดตอน รหัสหาย/กำกวม/ซ้ำ ให้หยุดพร้อมข้อความผิดพลาด

4. หลักฐานการทดสอบ

ผ่าน 66 automated tests ใน .venv รวม namespace, primary IDs, missing data, หลาย polypeptides/actions, CSV และ CLI มี fixture 11 ยาและ golden 5 แถวจากภาพโจทย์ ยืนยันค่าเริ่มต้น XML, header ตามภาพ และการเริ่มเลขใหม่ทุกหมวดตาม Bivalirudin

กลุ่มทดสอบสิ่งที่ยืนยัน
โครงสร้างต้นทางXML namespaces, primary IDs, nested drug, 4 หมวด, empty entries และการเรียงรายละเอียดโปรตีน
ความครบของข้อมูลDNA ไม่มี polypeptide, หลาย actions, หลาย polypeptides, คู่ ID/gene ที่มีข้อมูลหาย และโปรตีนหลายบทบาท
CSV และการตรวจสอบcomma/quote/newline/ภาษาไทย, รูปแบบหลักและตาราง, การตรวจจับค่าถูกแก้ แถวหาย แถวเกิน ลำดับผิด และ header ผิด
ความผิดพลาดและ CLIXML ขาดตอน/ไม่ใช่ XML, ไม่มี input, ID กำกวม/ซ้ำ, พาธชนกัน และการรักษาไฟล์เดิมเมื่อสกัดไม่สำเร็จ

XML จริงขนาด 1.58 GB ระบุ exported-on 2023-01-04 สกัดได้ 15,235 ยา / 29,279 entries ตัวตรวจอิสระเทียบทุก cell ทุกแถวผ่าน (status=passed) ตัวอย่างต้น/กลาง/ท้ายคือ DB00001, DB08565 และ DB17386 พร้อม SHA-256 และพาธ Python ใน venv

วัดใน process แยกบน Linux เครื่องนี้ ผลทั้งสองชุดผ่านการเทียบ XML/CSV ทุกแถว RAM ขึ้นกับยาตัวใหญ่ที่สุด parser buffer ชุด ID ที่ตรวจซ้ำ 3 แถวตัวอย่าง และรายละเอียด complexes ในรายงาน spool อยู่บนดิสก์ ชุดจำลองนี้ไม่มี complexes; ผลนี้ไม่ใช่เวลาหรือ RAM ของฐานจริงปี 2023

6. จุดกำกวมที่ต้องยืนยันกับผู้สอน

Total-IonChannel: สมมติให้คอลัมน์นี้นับ carriers ตามลำดับ 4 หมวด และเปิดเผยในโค้ด/ข้อความขณะรัน/JSON carriers ไม่ใช่คำพ้องกับ ion channels ทางชีววิทยา จึงยังต้องยืนยันนิยามคอลัมน์กับผู้สอน แม้ค่าที่เขียนตรงกับ XML

ภาพกับ XML ต่างกัน: DB00004 มี 3 targets ใน XML จริง แต่ภาพแสดง 2 DB00006 ยืนยันจาก XML ได้ counts 1,1,0,0 ต่างจากภาพ 1,1,0,1 และ C1q ของ Etanercept มี UniProt/gene 3 คู่ โปรแกรมรักษาทุกค่าจาก XML
